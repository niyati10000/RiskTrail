# HF_SPACES_DEPLOY.md — Hugging Face Spaces Deployment Guide & Security Checklist

This document details the deployment procedure for hosting the **RiskTrail** credit risk scoring and profit optimization dashboard on **Hugging Face Spaces (Streamlit SDK)**.

---

## 1. Security & Data Governance Checklist

Per [`docs/SECURITY_AND_ACCESS.md`](file:///docs/SECURITY_AND_ACCESS.md), verify each security gate before publishing:

- [x] **Zero Raw or Customer-Level Data**: Real customer datasets (`data/raw/`, `data/interim/`, `data/processed/`) are strictly gitignored in [`.gitignore`](file:///.gitignore).
- [x] **Synthetic Sample Only**: The demo operates exclusively on [`app/sample_data.parquet`](file:///app/sample_data.parquet) (50 synthetic records generated by [`src/data/create_sample.py`](file:///src/data/create_sample.py)), completely decoupled from any proprietary or competition records.
- [x] **Zero Secrets or API Keys**: No Kaggle credentials, Hugging Face tokens (`HF_TOKEN`), or private keys exist in any tracked files or commit history (`.env` is gitignored).
- [x] **Model Portability**: The saved LightGBM benchmark model is bundled at [`app/model.txt`](file:///app/model.txt), avoiding pickle deserialization vulnerabilities.
- [x] **Educational & Regulatory Disclaimers**: Explicit disclaimers are visibly displayed at the top of the application and in the README, clarifying that the demo is for research/education only and not certified for real credit decisions.

## 3. Step-by-Step Deployment Instructions

### Step 1: Create a Space on Hugging Face
1. Log in to [Hugging Face](https://huggingface.co).
2. Navigate to [huggingface.co/new-space](https://huggingface.co/new-space).
3. Set the Space name: `risktrail-demo`.
4. Select **Streamlit** as the Space SDK.
5. Select **Public** (or **Private** for internal testing).
6. Hardware: Select **CPU basic (free tier)** — the synthetic demo and LightGBM model require < 1 GB RAM.

### Step 2: Configure Git Remote
In your local repository terminal:

```bash
git remote add space https://huggingface.co/spaces/<YOUR_HF_USERNAME>/risktrail-demo
```

### Step 3: Verify Pre-Push Cleanliness
Run a git status and secrets check:
```bash
git status
git log -p -1
```

### Step 4: Push to Hugging Face Spaces
```bash
git push space main
```

*(If prompted for credentials, use your Hugging Face username and a Personal Access Token with write permissions from `https://huggingface.co/settings/tokens`)*

### Step 5: Verification & Smoke Test
1. Monitor the Hugging Face build log in the Space's **App** tab.
2. Confirm the app builds and serves at `https://huggingface.co/spaces/<YOUR_HF_USERNAME>/risktrail-demo`.
3. Verify interactive features:
   - Move the **Approval Cutoff Slider** (e.g., from 0.05 to 0.20) and verify the decision changes from APPROVE to DECLINE.
   - Click **Score**, **Profit Curve**, and **Why This Decision** tabs.
   - Verify that the horizontal SHAP reason code bar chart and 13-month statement trajectory render cleanly.
